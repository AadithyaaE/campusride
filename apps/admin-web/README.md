# admin-web

College transport admin dashboard (React + Vite + TypeScript). **Prototype** — started in
Feature 8 with live occupancy; since Feature 13 it is a single **transport control room**.

## Run

```bash
npm install
npm run dev          # http://localhost:5174 (backend CORS already allows it)
```

Sign in with a mock admin account, e.g. `admin1@campusride.demo` (no password; non-admin
accounts are refused). Backend URL: `VITE_API_BASE_URL` (default `http://localhost:8000/api/v1`).

## Transport control room (Feature 13)

One operational view, top to bottom: KPI cards (total buses, active trips, students,
passengers today) + alert summary · live fleet map (Leaflet/OSM: planned route lines, bus
labels coloured by status, deviated buses highlighted) + bus/route detail panel · live fleet
table with Route / Bus / Status filters · active buses · occupancy · route deviations ·
delays · alerts (active/resolved, mark read) · route management · today's schedule ·
usage analytics.

Backend endpoints (admins only — students and drivers get 403):

| Endpoint                                   | Used for                                                            | Poll |
| ------------------------------------------ | ------------------------------------------------------------------- | ---- |
| `GET /admin/overview`                      | KPI cards, exception counts                                         | 3 s  |
| `GET /admin/fleet`                         | map, table, active buses, occupancy, deviations, delays, bus detail | 3 s  |
| `GET /alerts?active=true`                  | alert summary + list + bus detail                                   | 3 s  |
| `GET /admin/routes`, `GET /admin/schedule` | route management/detail, schedule                                   | 15 s |
| `GET /admin/analytics`                     | analytics (live block + synthetic block)                            | 20 s |
| `GET /routes/{id}`                         | route geometry + ordered stops                                      | once |

Each resource is polled by ONE hook in `src/dashboard/ControlRoom.tsx` and shared by every
panel. Every value (ETA to next stop, occupancy and crowding, delay, route status, operational
status, passengers today) is computed by the backend (`backend/app/services/admin_service.py`
over the existing ETA / occupancy / route-anomaly / alert services). Filters select backend
rows by backend fields. Route and schedule management are **read-only** (no mutation APIs
exist). Analytics history is **Synthetic demo data** — deterministic, generated by the
backend from `SEED` + service date, shown in its own hatched block, never mixed with live
values.

The Feature 8–11 views below live on inside the control room (bus detail → route monitor,
trip boarding; alerts panel).

## Earlier views (now inside the control room)

**Live occupancy** — every bus on an active trip: bus, route direction, trip, occupancy /
capacity, % occupied, seats available, QR boardings on the trip, last update (campus time).
It polls `GET /api/v1/buses` every 3 s — the same backend state the student dashboard reads —
so a QR scan appears on the next poll. Click a trip to see its boarding events
(`GET /api/v1/trips/{trip_id}/boarding`, admins see every event).

Every number is displayed exactly as the backend computed it (`backend/app/services/capacity.py`):

```
occupancy = min(capacity, synthetic simulator headcount + QR boardings on the current trip)
```

Nothing is counted or derived in the browser, and there is no separate frontend state.

**Route deviation** (Feature 10) — a _Route status_ column (Normal / Minor deviation /
Major deviation + metres off route). Select a bus (its number) to open the route monitor:
status, distance, fix time and a Leaflet map of the backend's planned route, the tracked bus
position and the nearest point of the route (`GET /api/v1/buses/{id}/route-status`). The
demo buttons **Normal / Simulate Minor Deviation / Simulate Major Deviation** call
`POST /api/v1/sim/route-deviation` for that bus: the backend simulator moves the bus's
SYNTHETIC GPS sideways — the route remains the planned route. **Active alerts**
(`GET /api/v1/alerts?active=true`) shows the one alert raised when a bus enters a major
deviation; it clears when the bus returns. Nothing is measured or classified in the browser.

**Active alerts** (Feature 11) — fleet/operational alerts from the backend
`AlertService` (`GET /api/v1/alerts?active=true`): major ROUTE DEVIATION, BUS DELAYED and
CAPACITY WARNING, newest first, with severity text, an unread badge and **Mark read**
(`PATCH /api/v1/alerts/{id}/read`). Students' personal notifications never appear here.
Alerts are raised on backend state changes (never by polling); the panel polls every 3 s.

## Known limitations

- Mock authentication only (as the rest of the prototype).
- The small API client (`src/api/client.ts`) mirrors the student app's client; moving both
  into `packages/api-client` is planned.
- Polling, not WebSockets.
